# האתר למדריכי ריצות ארוכות · סמסטר 2027א

אתר לימוד לקורס מדריכי ריצות ארוכות: כל חומר המצגות בשפה פשוטה, עם בוחן בסוף כל פרק. האתר מתארח ב-Cloudways ומתעדכן אוטומטית בכל push ל-`main` (ראו "פריסה" למטה).

## קבצים

- `index.html`: העמוד הראשי, עם קישור לכל נושא ופס התקדמות.
- `anatomy.html`: האנטומיה של הריצה (5 פרקים).
- `physiology.html`: הפיזיולוגיה של הריצה (7 פרקים, כולל מחשבון קרבונן).
- `theme.js`: כפתור מעבר בין מצב כהה למצב בהיר (הבחירה נשמרת בדפדפן).
- `sync.js`: כפתור "שמירת התקדמות", כניסה עם קוד במייל, וסנכרון ההתקדמות מול השרת.
- `api/`: שרת PHP קטן (בקשת קוד, אימות, שמירה וטעינה של התקדמות).
- `.github/workflows/cloudways-deploy.yml`: העלאה אוטומטית ל-Cloudways בכל push.

כל עמוד עומד בפני עצמו: ה-CSS, ה-JavaScript והתמונות נמצאים בתוך הקובץ. ההתקדמות נשמרת ב-`localStorage` של הדפדפן. מי שמתחבר עם מייל מקבל גם שמירה בשרת, וכך יכול להמשיך מכל מכשיר. אם ה-API לא זמין (למשל כשפותחים קובץ מהמחשב), הכפתור לא מופיע והאתר עובד כרגיל.

## שמירת התקדמות (כניסה עם מייל)

1. המשתמש מזין כתובת מייל ומקבל קוד בן 6 ספרות (בתוקף ל-10 דקות).
2. אחרי הקוד הוא נשאר מחובר 60 יום (עוגייה מסוג httpOnly).
3. כל שינוי במפתחות `anat.*` ו-`phys.*` ב-`localStorage` נשמר בשרת. בכניסה ממכשיר אחר, פרקים שהושלמו מתאחדים משני הצדדים.

מגבלות: קוד אחד לדקה לכל מייל, 5 בשעה לכל מייל, 20 בשעה לכל כתובת IP, ו-5 ניסיונות לכל קוד.

המיילים נשלחים עם `mail()` של PHP, דרך ה-Add-on של Elastic Email בשרת. כתובת השולח (`mail_from` ב-`config.php`) חייבת להיות בדומיין שמאומת ב-Elastic Email.

**הגדרה חד-פעמית בצד השרת** (לא דרך git):
1. מריצים את `api/schema.sql` ב-phpMyAdmin (Launch Database Manager ב-Cloudways).
2. יוצרים את `api/config.php` (מעתיקים מ-`api/config.example.php`) ישירות בשרת, עם פרטי בסיס הנתונים מ-Access Details.

`api/config.php` נמצא ב-`.gitignore` בכוונה. הוא לא אמור להגיע לריפו לעולם.

## הוספת נושא חדש

1. מוסיפים קובץ `<נושא>.html`.
2. מוסיפים כרטיס ב-`index.html` (עם `data-key` ו-`data-total` לפס ההתקדמות).
3. מוסיפים קישור בסרגל הניווט (`nav.sb`) בכל העמודים.

## פריסה (Cloudways + GitHub Actions)

כל `push` ל-`main` מפעיל את `.github/workflows/cloudways-deploy.yml`, שקורא ל-API של Cloudways כדי למשוך (`git pull`) את הקוד העדכני לאפליקציה. הענף (`main`) ותיקיית היעד (`public_html`) קבועים בקובץ. שלושת הסודות הנדרשים (`CLOUDWAYS_API_KEY`, ובו Access Token של Cloudways, `CLOUDWAYS_SERVER_ID` ו-`CLOUDWAYS_APP_ID`) מוגדרים ב-Settings → Secrets and variables → Actions של הריפו.
